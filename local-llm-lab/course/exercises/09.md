## 실습 9-1 (필수) · 내 기계의 천장 계산하기

```python
step_bytes = (sum(nbytes(w) + nbytes(s) for w, s in Q.values())
              + nbytes(W["model.embed_tokens.weight"])         # lm head
              + n_layers * 2 * n_kv * MAX_LEN * hd * 2)          # KV 버퍼
print(f"스텝마다 읽는 양 ≈ {step_bytes / 1e6:.0f} MB")
print(f"→ {step_bytes * ours_rate / 1e9:.0f} GB/s (M3 Pro 메모리 대역폭 150 GB/s)")
```

M3 Pro에서는 870 MB × 92 tok/s ≈ 80 GB/s, 이론 대역폭 150 GB/s의 절반 정도였습니다.

**할 일**
1. 내 기계의 이론 메모리 대역폭을 제조사 사양에서 찾습니다(Apple Silicon은 칩 사양 페이지에 GB/s로 나옵니다).
2. `09_compare.py`를 실행해 세 엔진의 첫 토큰과 tok/s를 기록합니다.
3. 아래 표를 채웁니다.

| 엔진 | 스텝당 읽는 양 | 측정 tok/s | 실효 GB/s | 천장 tok/s (= 이론 대역폭 ÷ 읽는 양) | 천장 대비 % |
|---|---|---|---|---|---|
| 우리 (INT8) | 코드 출력값 | | | | |
| qwen3:0.6b-fp16 | 약 1.2 GB | | | | |
| qwen3:0.6b (Q4) | 약 522 MB | | | | |

**기대 결과**
- M3 Pro 기준: 우리 80 GB/s(천장의 약 53%), `qwen3:0.6b-fp16`은 1.2 GB × 87 ≈ 104 GB/s(천장 125 tok/s의 3분의 2쯤).
- 세 엔진 모두 천장 아래에 있고, 읽는 양이 작을수록 tok/s가 높습니다.

**힌트**
- Ollama 쪽 읽는 양은 가중치만 넣은 근사값입니다. KV 캐시는 빠져 있으니 표에 그렇게 적어 두십시오.

## 실습 9-2 (선택) · KV 버퍼 낭비를 숫자로

KV 버퍼 117 MB는 1,024칸 전체를 읽는 값인데, 실제로 채운 칸은 650개 정도입니다.

**할 일**
`MAX_LEN`을 704로 줄여 실행하고, `step_bytes`, tok/s, 실효 GB/s가 어떻게 바뀌는지 기록합니다.

**기대 결과**
- 스텝당 읽는 양이 약 37 MB 줄어듭니다(117 MB × (1 − 704/1024)). tok/s도 조금 오르는지 확인합니다. 이 차이가 "채운 칸만 읽기"로 얻을 수 있는 상한입니다.
