## 실습 3-1 (필수) · 길이별 forward 시간으로 기울기 구하기

```python
for n in [1, 32, 128, 256, 512, ids.shape[1]]:
    ms = sorted(timed(lambda: forward(ids[:, :n])) for _ in range(3))[1]
    print(f"입력 {n:4}토큰 → {ms:6.1f} ms")
```

본문 실행 결과는 1토큰 19.5 ms, 32토큰 21.6 ms, 128토큰 44.4 ms, 256토큰 85.7 ms, 512토큰 182.3 ms, 638토큰 231.5 ms였습니다.

**할 일**
1. 길이 목록에 `64, 384`를 추가하고 내 기계에서 실행합니다.
2. 128토큰 이상 구간에서 "토큰 하나 늘 때마다 몇 ms 늘어나는지"(기울기)를 구합니다. 두 점으로 구해도 되고 `numpy.polyfit`을 써도 됩니다.
3. 1토큰 시간과 기울기로, 매 스텝 입력 전체를 넣는 방식에서 48토큰 생성에 드는 시간을 예측하고 실제 값과 비교합니다.

**기대 결과**
- 짧은 입력(1~32토큰)은 시간이 거의 같습니다. 이 구간은 계산량이 아니라 고정 비용이 지배합니다.
- 본문 값으로 구하면 128 → 512토큰 기울기는 (182.3 − 44.4) ÷ 384 ≈ 0.36 ms/토큰입니다.

**힌트**
- 예측: Σ(i=0..47) forward(638 + i) ≈ 48 × forward(638) + 기울기 × (0 + 1 + … + 47).

## 실습 3-2 (선택) · 300토큰이면 몇 배를 헛도나

```python
steps = 48
computed = sum(T + i for i in range(steps))
print(f"{steps}토큰 생성 동안 처리한 위치: {computed:,}개")
print(f"그중 처음 보는 위치: {T + steps - 1:,}개")
```

48토큰에서는 31,752개 대 685개, 약 46배였습니다.

**할 일**
`steps`를 300과 1,000으로 바꿔 두 숫자와 배수를 구합니다. 손으로 먼저 계산한 다음 코드로 확인합니다.

**기대 결과**
- 300토큰: 300 × 638 + (0 + … + 299) = 191,400 + 44,850 = 236,250개 대 937개, 약 252배.
- 답이 길어질수록 낭비가 길이에 비례해 커집니다.

## 실습 3-3 (선택) · 마지막 층에서도 같은가

def first_layer(ids):

    cos, sin = rope_tables(torch.arange(T, device=device))

    return block(x, 0, cos, sin, causal_mask(T))
