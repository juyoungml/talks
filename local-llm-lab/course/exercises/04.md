## 실습 4-1 (필수) · KV cache 직접 구현하기

출발점은 매 스텝 입력 전체를 넣는 코드입니다.

```python
def attention(x, L, cos, sin, mask):
    T = x.shape[1]
    p = f"model.layers.{L}.self_attn."
    q = (x @ W[p + "q_proj.weight"].T).view(1, T, n_q, hd)
    k = (x @ W[p + "k_proj.weight"].T).view(1, T, n_kv, hd)
    v = (x @ W[p + "v_proj.weight"].T).view(1, T, n_kv, hd)
    q = rope(rms_norm(q, W[p + "q_norm.weight"]).transpose(1, 2), cos, sin)
    k = rope(rms_norm(k, W[p + "k_norm.weight"]).transpose(1, 2), cos, sin)
    v = v.transpose(1, 2)
    ...

def forward(ids):
    T = ids.shape[1]
    cos, sin = rope_tables(torch.arange(T, device=device))
    mask = causal_mask(T)
    ...

def generate(ids, max_new=48, pick=greedy):
    ...
    for _ in range(max_new):
        next_id = pick(forward(ids))
        ...
        ids = torch.cat([ids, next_id], dim=1)
```

**할 일**
1. `cache`: 층마다 `(k, v)`를 담는 길이 28 리스트를 만듭니다.
2. `attention`: 이번에 들어온 위치의 k, v만 계산하고, 캐시에 있던 것 뒤에 이어 붙인 다음 캐시를 갱신합니다.
3. `forward(ids, cache, start)`: 위치 정보(RoPE)를 0이 아니라 `start`부터 매깁니다.
4. `causal_mask(T, start)`: 새 토큰 T개가 캐시 포함 `start + T`개 위치 중 어디까지 볼지 만듭니다. 모양은 `[T, start + T]`입니다.
5. `generate`: 처음 한 번 프롬프트 전체를 넣고(prefill), 그 뒤로는 고른 토큰 하나만 넣습니다(decode).

**확인**
아래 검증 코드를 파일 끝에 붙입니다. 캐시를 쓴 점수와, 빈 캐시로 처음부터 계산한 점수를 8스텝 비교합니다.

```python
cache, seq = new_cache(), ids
logits = forward(ids, cache)
worst, same = 0.0, 0
for _ in range(8):
    next_id = greedy(logits)
    seq = torch.cat([seq, next_id], dim=1)
    logits = forward(next_id, cache, start=seq.shape[1] - 1)
    full = forward(seq, new_cache())  # 빈 캐시 = 처음부터 전부
    worst = max(worst, (logits - full).abs().max().item())
    same += int(greedy(logits) == greedy(full))
print(f"8스텝 최대 차이 {worst:.3f} | 1등 토큰 일치 {same}/8")
```

**기대 결과**
- `8스텝 최대 차이`가 0.1 미만(본문 0.062), `1등 토큰 일치 8/8`.
- 생성 결과 48토큰이 캐시 없을 때와 같습니다.
- decode 스텝이 캐시 없을 때의 10분의 1 근처로 줄어듭니다(본문 240 ms → 23 ms).

**힌트**
1. k의 모양은 transpose 뒤 `[1, 8, 위치 수, 128]`입니다. 위치 축은 `dim=2`입니다.
2. 최대 차이가 크다면 RoPE 위치부터 확인하십시오. decode 때 새 토큰의 위치는 0이 아니라 지금까지의 길이입니다.
3. mask는 "새 토큰의 위치 ≥ 볼 위치"입니다. `q = torch.arange(start, start + T)[:, None]`, `k = torch.arange(start + T)[None, :]`로 놓고 비교해 보십시오.
4. 워밍업 호출이 캐시를 더럽히지 않게, 워밍업과 실제 생성은 서로 다른 캐시를 씁니다.

## 실습 4-2 (선택) · 컨텍스트 길이별 KV 메모리 표

```python
size = W["model.embed_tokens.weight"].element_size()
per_token = n_layers * 2 * n_kv * hd * size
```

토큰 하나당 112 KB, 646토큰이면 74.1 MB, 최대 40,960토큰이면 4.7 GB였습니다.

**할 일**
`[1024, 2048, 4096, 8192, 40960]` 각 길이의 KV 크기(MB)를 출력하고, 가중치 크기 1.2 GB를 넘는 첫 길이를 찾습니다. 같은 표를 k, v도 16헤드(`n_q`)로 저장했을 때로 한 번 더 만듭니다.

**기대 결과**
- 8헤드: 8,192토큰에서 약 0.94 GB, 그다음 단계에서 가중치를 넘습니다. 16헤드로 저장하면 모든 칸이 두 배입니다(GQA가 줄여 주는 양).
