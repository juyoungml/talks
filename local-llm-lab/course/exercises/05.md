## 실습 5-1 (필수) · decode 한 스텝의 연산 수 세기

attention 하나의 연산 수를 센 도구가 파일에 이미 있습니다.

```python
class CountOps(TorchDispatchMode):  # PyTorch가 실제로 실행한 연산을 센다
    def __init__(self):
        super().__init__()
        self.ops = []
    def __torch_dispatch__(self, func, types, args=(), kwargs=None):
        self.ops.append(func.__name__.split(".")[0])
        return func(*args, **(kwargs or {}))
```

본문은 decode 한 스텝 전체의 연산 수를 손으로 짠 attention에서 3,190번, SDPA에서 2,546번으로 셌습니다.

**할 일**
1. 프롬프트로 캐시를 채운 뒤, `forward(next_id, cache, start=pos)` 한 번을 `with CountOps() as c:` 안에서 실행해 `len(c.ops)`를 출력합니다.
2. `collections.Counter(c.ops).most_common(10)`으로 가장 많이 실행된 연산 10개를 봅니다.
3. `attention` 안을 손으로 짠 다섯 줄로 되돌려 같은 측정을 합니다(아래 코드).

```python
k = k.repeat_interleave(n_q // n_kv, dim=1)
v = v.repeat_interleave(n_q // n_kv, dim=1)
scores = (q @ k.transpose(-1, -2)) * hd**-0.5
scores = scores.masked_fill(~mask, float("-inf"))
out = scores.float().softmax(-1).to(dtype) @ v
```

**기대 결과**
- SDPA 2,546번, 손으로 3,190번 근처(PyTorch 버전에 따라 조금 다를 수 있음). 차이 644번을 28층으로 나누면 층마다 23번입니다.
- 많이 나오는 연산은 행렬곱(`mm`), 곱셈, 덧셈, `view` 같은 것입니다. 한 층 안의 작은 연산이 28번 반복됩니다.

**힌트**
- 캐시를 채운 상태에서 세어야 decode 스텝이 됩니다. `cache = new_cache(); logits = forward(ids, cache); next_id = greedy(logits)`를 먼저 실행하십시오.

## 실습 5-2 (선택) · decode 모양에서 두 attention 비교

```python
def inputs(Tq, Tk):
    r = lambda h, t: torch.randn(1, h, t, hd, device=device, dtype=dtype)
    return r(n_q, Tq), r(n_kv, Tk), r(n_kv, Tk), causal_mask(Tq, Tk - Tq)
```

본문은 prefill 모양(`inputs(n, n)`)만 쟀습니다. 638토큰에서 손으로 3.9 ms, SDPA 1.5 ms였습니다.

**할 일**
`inputs(1, 640)`, `inputs(1, 2048)`로 decode 모양의 시간을 `timed(manual, ...)`, `timed(fused, ...)`로 잽니다.

**기대 결과**
- decode 모양에서는 둘 다 1 ms보다 훨씬 짧고 차이도 작습니다. 점수 행렬이 `[16, 1, 640]`, 40 KB뿐이라 옮길 데이터가 거의 없습니다. decode에서 SDPA가 빨라진 이유는 이 시간이 아니라 연산 수(실습 5-1)라는 것을 확인할 수 있습니다.
