## 실습 2-1 (필수, 자동 채점) · 샘플링 함수 직접 만들기

`steps/02_generate.py`에는 정답 `sample`이 이미 들어 있습니다. 보지 않고 직접 만들어 봅니다.

**할 일**
`work/my_sampling.py`라는 새 파일에 아래 함수 하나만 씁니다.

```python
import torch

def sample(logits, temperature=0.6, top_k=20, top_p=0.95):
    """logits: [1, 어휘 수]. 반환: [1, 1] 토큰 번호 (torch.long)"""
    ...
```

순서는 Ollama 기본 설정과 같습니다.

1. **temperature**: 점수를 `temperature`로 나눈 뒤 softmax로 확률을 만듭니다.
2. **top_k**: 확률 상위 `top_k`개만 남깁니다.
3. **top_p**: 남은 것을 확률 큰 순서로 더해 가며, 누적이 `top_p`에 닿는 토큰까지 남깁니다. 누적을 넘기는 그 토큰도 포함합니다.
4. 남은 확률을 다시 합이 1이 되게 나누고 하나를 뽑습니다(`torch.multinomial`).

**확인**

```bash
uv run python course/checks/check_02_sampling.py work/my_sampling.py
```

모델 없이 합성 점수로 7가지를 검사합니다(1초 안팎). 실제 모델로도 확인하려면 `--real`을 붙입니다. 가중치를 불러와 회의록 첫 토큰을 1,000번 뽑고, 본문 결과(`'1'` 868번, `'-'` 132번, `'회의'` 0번)와 같은 분포인지 봅니다.

```bash
uv run python course/checks/check_02_sampling.py work/my_sampling.py --real
```

**기대 결과**
- 모든 항목이 `PASS`. `--real`에서는 `'1'`이 1,000번 중 840~900번, `'회의'`는 0번입니다. 뽑는 방식이 달라서 868번이 정확히 나오지 않아도 통과합니다.

**힌트**
1. `probs.topk(top_k)`는 `(값, 번호)` 두 개를 돌려줍니다. 뽑은 다음에는 "몇 번째"를 "토큰 번호"로 바꿔야 합니다(`gather`).
2. top_p에서 `cumsum < top_p`로 자르면, 1등 확률이 0.97일 때 1등까지 잘려 남는 토큰이 없습니다. "나보다 **앞** 토큰들의 누적"과 비교하십시오.
3. `torch.multinomial`은 합이 1이 아니어도 동작하지만, 체커는 분포를 보므로 남긴 확률끼리의 비율이 맞아야 합니다.

## 실습 2-2 (선택) · min-p 추가하기

min-p는 1등 확률의 일정 비율보다 낮은 토큰을 버립니다. Ollama의 `min_p` 옵션이 이것입니다.

**할 일**
`sample`에 `min_p=0.0` 인자를 추가합니다. temperature 적용 후 확률이 `min_p × (1등 확률)`보다 작은 토큰을 버리는 단계를 top_k 앞에 넣습니다. `temperature=1.5`에서 `min_p=0`과 `min_p=0.05`로 각각 첫 토큰을 1,000번 뽑아 나온 토큰 종류 수를 비교합니다.

```python
logits = forward(ids)
torch.manual_seed(0)
picks = torch.cat([sample(logits, temperature=1.5, min_p=0.05) for _ in range(1000)]).flatten()
print(len(picks.unique()), "종류")
```

**기대 결과**
- temperature가 높으면 분포가 평평해져 종류가 늘어나고, `min_p=0.05`를 주면 종류가 줄어듭니다.
