## 실습 8-1 (필수) · 층마다 양자화 오차 재기

```python
w = W.pop(key + ".weight").float()
scale = w.abs().amax(dim=1) / 127            # 행마다 가장 큰 값이 127이 되게
Q[key] = ((w / scale[:, None]).round().to(torch.int8), scale.to(dtype))
```

1층 `q_proj` 첫 행은 가장 큰 값이 0.0518, scale이 0.000408이었고, 행 전체의 평균 오차는 값 크기의 1% 정도였습니다.

**할 일**
1. 양자화 루프 안에서 되돌린 값 `w_hat = q.float() * scale[:, None]`을 만들고, 행렬마다 상대 오차 `(w_hat - w).abs().mean() / w.abs().mean()`을 구합니다.
2. 7종(q, k, v, o, gate, up, down) × 28층 결과를 표로 출력하고, 오차가 가장 큰 행렬 세 개를 찾습니다.
3. 1층 `q_proj` 첫 행의 상대 오차가 1% 근처인지 확인합니다.

**기대 결과**
- 대부분 1% 안팎. 행 안에 유난히 큰 값이 하나 있으면 눈금이 커져서 나머지 값의 오차가 커집니다. 오차가 큰 행렬은 그런 행이 많은 행렬입니다.

**힌트**
- `W.pop`이 원본을 지우므로, 오차를 재려면 `pop`하기 전에 `w`를 받아 두고 비교한 다음 버리십시오. 원본을 계속 들고 있으면 메모리가 두 배가 됩니다.

## 실습 8-2 (선택) · 되돌려서 곱하면 왜 느린가

본문에서는 처음에 곱하기 직전에 FP16으로 되돌렸더니 decode 스텝이 24 ms에서 105 ms로 느려졌습니다. 직접 재현합니다.

**할 일**
`linear`를 아래처럼 바꿔 스텝별 ms를 기록한 뒤 원래대로 되돌립니다.

```python
# 원래
def linear(x, key):
    w, scale = Q[key]
    out = torch.ops.aten._weight_int8pack_mm(x.reshape(-1, x.shape[-1]), w, scale)
    return out.view(*x.shape[:-1], -1)

# 실험
def linear(x, key):
    w, scale = Q[key]
    return x @ (w.to(dtype) * scale[:, None]).T
```

**기대 결과**
- 실험 버전은 FP16 버전(`steps/07_compile.py`)보다도 느립니다. INT8을 읽고, FP16 사본을 메모리에 쓰고, 그 사본을 다시 읽기 때문입니다.
