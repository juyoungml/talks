## 실습 1-1 (필수) · 다른 질문의 첫 토큰과 상위 10개

`request`를 바꿔서 모델이 답을 어떻게 시작하는지 봅니다.

```python
request = "회의록의 결정 사항 세 가지를 한국어로 정리해줘."
```

```python
logits = forward(ids)
print(logits.shape)
probs = logits[0].float().softmax(-1)
for p, i in zip(*probs.topk(5)):
    print(f"{i.item():>6}  {tokenizer.decode(i)!r:8} {p.item():6.1%}")
```

**할 일**
1. `request`를 "회의록을 영어로 한 문장으로 요약해줘."로 바꿉니다.
2. `topk(5)`를 `topk(10)`으로 바꿉니다.
3. 입력 토큰 수(`ids.shape`)와 상위 10개를 기록합니다.

**기대 결과**
- 입력 토큰 수가 638에서 조금 달라집니다(요청 문장 길이만큼).
- 원래 질문은 `'1'` 60.0%, `'-'` 18.9%로 "목록을 무엇으로 시작할까"를 고민했습니다. 영어 요약을 시키면 상위 토큰이 영어 단어 조각으로 바뀝니다.

**힌트**
- 토큰 번호와 글자를 같이 보려면 `tokenizer.decode(i)`를 씁니다. 바이트 조각이면 `�`로 보입니다.

## 실습 1-2 (선택) · 내 글의 바이트 조각 비율

회의록 638토큰 중 106개(17%)는 사전에 없는 글자를 UTF-8 바이트로 쪼갠 조각이었습니다. 직접 세어 봅니다.

**할 일**
아래 함수를 `work/01_first_token.py` 끝에 붙이고, 회의록과 영어 문단 하나, 직접 쓴 한국어 문단 하나로 실행합니다.

```python
def fragments(text):
    ids = tokenizer(text).input_ids
    bad = sum("�" in tokenizer.decode([i]) for i in ids)
    return len(ids), bad

print(fragments(text))
```

**기대 결과**
- 템플릿을 포함한 `text`에서 `(638, 106)` 근처가 나옵니다.
- 영어 문단은 조각이 거의 없습니다.

**힌트**
- 한 글자가 바이트 조각 2~3개로 나뉘면 조각마다 `�`가 나옵니다. 그래서 디코딩 결과에 `�`가 있는지로 셉니다.

## 실습 1-3 (선택) · `synchronize()`를 빼고 재기

```python
for _ in range(4):
    sync()
    start = time.perf_counter()
    next_id = forward(ids).argmax(-1)
    sync()
    times.append((time.perf_counter() - start) * 1000)
```

**할 일**
두 번째 `sync()`를 지우고 다시 잽니다. 그다음 `sync()`를 지운 상태에서 `next_id.item()`을 시간 재는 구간 안에 넣고 다시 잽니다.

**기대 결과**
- `sync()`를 지우면 시간이 비정상적으로 짧아집니다(GPU에 일을 넘긴 시각까지만 잡힘).
- `.item()`을 넣으면 다시 원래 시간(본문 223 ms) 근처가 나옵니다. `.item()`은 값을 CPU로 가져와야 하므로 GPU가 끝날 때까지 기다리기 때문입니다.
