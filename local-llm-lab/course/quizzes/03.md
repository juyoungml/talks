**3.** 다음 코드는 프롬프트 638토큰과, 한 토큰을 더 붙인 639토큰을 1층에 넣고 앞쪽 638개 위치를 비교합니다.

```python
T = ids.shape[1]
longer = torch.cat([ids, greedy(forward(ids))], dim=1)
diff = (first_layer(ids) - first_layer(longer)[:, :T]).abs().max()
```

출력은 `1층 출력, 앞 638개 위치의 최대 차이: 0.0000`이었습니다. 차이가 0인 이유를 아래 mask 코드와 연결해서 쓰십시오.

```python
def causal_mask(T):
    return torch.ones(T, T, dtype=torch.bool, device=device).tril()
```

**4.** 다음 코드의 출력은 `31,752개`와 `685개`입니다.

```python
steps = 48
computed = sum(T + i for i in range(steps))
print(f"{steps}토큰 생성 동안 처리한 위치: {computed:,}개")
print(f"그중 처음 보는 위치: {T + steps - 1:,}개")
```

T = 638일 때 31,752가 나오는 계산을 풀어 쓰고, 두 번째 식에 `- 1`이 붙는 이유를 쓰십시오.

**5.** 새 토큰이 각 층에서 앞쪽 위치로부터 가져가는 값만 저장해 두면 앞쪽을 다시 계산하지 않아도 됩니다. 아래 attention 코드에서 그 값은 무엇입니까?


- (b) k와 v

**6.** 31,752 ÷ 685는 약 몇 배입니까? 이 숫자가 뜻하는 것을 한 문장으로 쓰십시오.

## 정답과 해설

1. **(b)** 첫 토큰은 638토큰을 처음 읽으니 오래 걸리는 게 당연하지만, 그 뒤 스텝도 같은 양을 매번 다시 계산하고 있습니다. 입력이 한 토큰씩 길어지니 조금씩 더 느려집니다.
2. 1토큰 forward가 약 20 ms이므로 스텝 하나 약 **20 ms**, 초당 약 **50토큰**입니다. 지금은 매 스텝 638토큰 넘게 넣고 있어서 230 ms 이상 걸립니다.
3. `tril()`로 만든 mask는 각 위치가 **자기와 그 앞만** 보게 합니다. 639번째 토큰이 뒤에 붙어도 앞쪽 638개 위치는 그것을 볼 수 없으니 계산 결과가 바뀌지 않습니다.
4. 스텝 i(0부터)에 넣는 길이는 638 + i이므로 638 × 48 + (0 + 1 + … + 47) = 30,624 + 1,128 = **31,752**. 마지막으로 고른 48번째 토큰은 다시 forward에 넣지 않으므로 처음 보는 위치는 638 + 48 − 1 = **685**입니다.
5. **(b)** 새 토큰의 q는 앞쪽 위치의 k와 점수를 매기고, 그 점수로 앞쪽 위치의 v를 섞습니다. 앞쪽 위치의 q와 MLP 결과는 다시 쓰지 않습니다.
6. 약 **46배**. 48스텝 동안 꼭 필요한 계산의 46배를 하고 있었다는 뜻입니다.
