**5.** Ollama의 기본 샘플링 설정(temperature 0.6, top_k 20, top_p 0.95)을 옮긴 함수입니다.

```python
def sample(logits, temperature=0.6, top_k=20, top_p=0.95):
    probs = (logits.float() / temperature).softmax(-1)
    probs, idx = probs.topk(top_k)              # 상위 20개만 남기고
    keep = probs.cumsum(-1) - probs < top_p     # 누적 95% 안쪽만 남긴다
    probs = probs * keep
    choice = torch.multinomial(probs / probs.sum(), 1)
    return idx.gather(-1, choice)
```

temperature를 적용한 뒤 상위 확률이 `[0.97, 0.02, 0.01, ...]`라고 합시다. `keep` 줄이 지금처럼 `probs.cumsum(-1) - probs < top_p`일 때와, `probs.cumsum(-1) < top_p`로 바꿨을 때 남는 토큰은 각각 몇 개입니까?

**6.** 첫 토큰의 원래 확률은 `'1'` 60.0%, `'-'` 18.9%, `'회의'` 7.3%였습니다. temperature 0.6, top_k 20, top_p 0.95로 뽑는 `sample` 함수로 같은 점수에서 1,000번 뽑았더니 `'1'` 868번, `'-'` 132번이 나왔습니다.

틀린 설명을 고르십시오.

- (a) greedy(`logits.argmax(-1, keepdim=True)`)였다면 1,000번 모두 `'1'`이 나온다.
- (b) temperature 0.6으로 나누면 1등 쪽으로 확률이 몰려서 `'1'`이 87% 근처가 된다.
- (c) `'회의'`가 한 번도 안 나온 것은 top_k 20 밖이었기 때문이다.
- (d) `'1'`과 `'-'`만으로 누적 확률이 0.95를 넘어서 그 뒤 토큰이 잘렸다.

**7.** 이 코스는 속도를 비교할 때 계속 `greedy`를 쓰고, Ollama도 temperature 0으로 맞춥니다. 이유를 두 가지 고르십시오.

- (a) sampling은 forward 한 번에 비하면 시간이 거의 들지 않아 속도 비교에 영향이 없다.
- (b) greedy는 같은 입력이면 늘 같은 답이 나와서, 코드를 고친 뒤에도 결과가 그대로인지 비교하기 쉽다.
- (c) greedy는 sampling보다 forward를 덜 불러서 tok/s가 높게 나온다.
- (d) temperature 0이면 Ollama가 내부 캐시를 꺼서 우리 코드와 조건이 같아진다.
- (e) greedy가 sampling보다 늘 더 좋은 답을 내기 때문이다.

## 정답과 해설

1. **`forward(ids)`로 다음 토큰 점수를 받는다** → **`pick`(greedy)으로 가장 높은 점수의 토큰을 고른다** → **`<|im_end|>`(EOS)이면 멈춘다** → **고른 토큰을 `ids` 끝에 붙이고 처음으로 돌아간다**. 점수 계산 → 토큰 선택 → 종료 검사 → 입력 끝에 붙이기 순서입니다. EOS 검사가 `torch.cat`보다 앞에 있으므로 `<|im_end|>`는 입력에 붙지 않습니다.
2. (b). 스텝마다 `ids`가 한 토큰씩 길어지므로 638토큰에 맞춰 만든 cos, sin, mask는 639토큰 입력에 모양이 맞지 않습니다. 계산 자체는 그대로이고, 입력 길이를 보고 매번 만들도록 바꾼 것입니다.
3. **바이트 조각** / **깨진 글자 `�`** / **완성될 때까지**. "렌" 같은 글자는 바이트 조각 2~3개로 나뉩니다. 조각 하나만 디코딩하면 깨진 글자 `�`가 나오므로, 글자가 완성될 때까지 기다렸다가 찍습니다.
4. (c). 매 스텝 `forward(ids)`에 **입력 전체**를 넣습니다. 첫 토큰은 Ollama도 프롬프트 전체를 읽어야 하니 비슷하지만, 그다음부터 우리는 매 스텝 638토큰 넘게 다시 계산합니다.
5. `cumsum - probs < top_p` **1개**, `cumsum < top_p` **0개**. `cumsum - probs`는 "나보다 앞 토큰들의 누적 확률"이라 1등은 0 < 0.95로 남고, 2등은 0.97 < 0.95가 아니라 잘립니다(1개). 그냥 `cumsum`이면 1등부터 0.97 < 0.95가 거짓이라 0개가 남고, `probs / probs.sum()`이 0 ÷ 0이 됩니다.
6. (c). `'회의'`는 3등이라 top_k 20 안에 있습니다. temperature 0.6을 적용하면 `'1'`과 `'-'`의 누적 확률이 0.95를 넘으므로 `'회의'`는 top_p에서 잘립니다.
7. (a), (b). sampling은 forward 한 번에 비해 시간이 거의 들지 않아 속도 비교에 영향이 없습니다. 대신 greedy는 같은 입력이면 늘 같은 답이 나와서, 코드를 고친 뒤 결과가 그대로인지 비교하기 쉽습니다.
