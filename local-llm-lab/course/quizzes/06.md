# 6강 퀴즈 · 메모리 미리 잡아두기 (static cache)

6문항 · 5문항 이상 맞히면 통과입니다. 코드는 `steps/05_sdpa.py`, `steps/06_static_cache.py`, 숫자는 6강 본문과 `examples/steps/06_static_cache.pass1.txt`에서 그대로 가져왔습니다.

---

**1.** 바꾸기 전의 캐시 코드입니다.

```python
if cache[L] is not None:  # 앞에서 계산해 둔 k, v 뒤에 새 것만 붙인다
    k = torch.cat([cache[L][0], k], dim=2)
    v = torch.cat([cache[L][1], v], dim=2)
cache[L] = (k, v)
```

모델은 28층입니다. 토큰 하나를 생성할 때마다 새로 만들어지는 캐시 텐서는 몇 개이고, 그 텐서들의 모양은 스텝마다 어떻게 됩니까?

**2.** 바꾼 뒤의 캐시 코드입니다.

```python
MAX_LEN = 1024  # 캐시에 담을 수 있는 최대 토큰 수

def new_cache():
    shape = (1, n_kv, MAX_LEN, hd)  # 층마다 (k, v) 버퍼를 처음에 한 번만 잡는다
    return [(torch.zeros(shape, dtype=dtype, device=device),
             torch.zeros(shape, dtype=dtype, device=device)) for _ in range(n_layers)]

# attention 안
K, V = cache[L]
K.index_copy_(2, pos, k)
V.index_copy_(2, pos, v)
k, v = K, V
```

`index_copy_(2, pos, k)`가 하는 일을 한 문장으로 쓰십시오.

**3.** 위 코드는 채운 부분만 잘라 주지 않고 `K, V` 버퍼 전체(1,024칸)를 attention에 넘깁니다. 아직 안 채운 칸은 아래 mask가 처리합니다.

```python
def causal_mask(pos):
    # 새 토큰들(위치 pos)이 캐시 MAX_LEN칸 중 어디까지 볼지. 빈 칸은 못 본다
    k = torch.arange(MAX_LEN, device=device)[None, :]
    return k <= pos[:, None]
```

쓸데없는 칸까지 계산하면서도 버퍼 전체를 넘기는 이유는 무엇입니까?

**4.** 위치를 넘기는 방식이 바뀌었습니다.

```python
# 전: 파이썬 정수
logits = forward(next_id, cache, start=pos)
pos += 1

# 후: GPU 위의 텐서
pos = torch.tensor([T], device=device)
...
logits = forward(next_id, cache, pos)
pos += 1
```

다음에 적용할 `torch.compile`은 "같은 모양, 같은 값"을 가정하고 코드를 만들고, 그 가정이 깨지면 다시 컴파일합니다. 위치를 텐서로 바꾼 이유를 이 성질과 연결해서 쓰십시오.

**5.** 다음 코드의 출력을 쓰십시오. (`n_layers = 28`, `n_kv = 8`, `hd = 128`, FP16)

```python
pos = torch.tensor([700], device=device)
K = new_cache()[0][0]
print("mask", list(causal_mask(pos).shape), "| K 버퍼", list(K.shape))
reserved = n_layers * 2 * K.numel() * K.element_size()
print(f"미리 잡은 KV 버퍼: {reserved / 1e6:.1f} MB ({MAX_LEN}토큰분)")
```

**6.** 바꾸기 전과 후의 실행 결과입니다(예시 출력).

```
전: 첫 토큰 182 ms | 이후 44.5 tok/s (48토큰)
후: 첫 토큰 233 ms | 이후 43.9 tok/s (48토큰)
```

맞는 해석을 고르십시오.

- (a) decode가 두 배 빨라졌다.
- (b) decode 속도는 그대로이고, 첫 토큰은 prefill이 1,024칸 전체를 보고 mask로 가리느라 느려졌다.
- (c) 첫 토큰과 decode 모두 빨라졌다.
- (d) KV 메모리 사용량이 줄어서 첫 토큰이 느려졌다.

## 정답과 해설

1. **56개**(28층 × k, v). `torch.cat`은 기존 텐서에 덧붙이는 게 아니라 한 칸 더 큰 텐서를 새로 만들어 통째로 복사하므로, 모양이 매 스텝 한 칸씩 커집니다.
2. 버퍼 `K`의 위치 축(2번 축)에서 `pos`가 가리키는 칸에 새 `k`를 써 넣습니다. 새 텐서를 만들지 않으므로 버퍼 크기는 그대로이고, 채우는 칸만 하나씩 오른쪽으로 갑니다.
3. 매 스텝 attention에 들어가는 텐서 모양을 **똑같이** 만들기 위해서입니다. 모양이 고정되어야 `torch.compile`로 한 가지 모양에 맞춘 코드를 만들 수 있습니다. 안 채운 칸은 `k <= pos` 조건이 거짓이라 mask로 가려집니다.
4. 파이썬 정수는 "값"으로 취급되어, 스텝마다 바뀌면 그때마다 다시 컴파일합니다. 텐서 안의 값은 바뀌어도 모양이 같으면 같은 코드를 씁니다. 그래서 `pos += 1`도 GPU 위의 텐서에서 일어나게 합니다.
5. `mask [1, 1024] | K 버퍼 [1, 8, 1024, 128]`, `미리 잡은 KV 버퍼: 117.4 MB (1024토큰분)`. 28 × 2 × (8 × 1,024 × 128) × 2바이트 = 117,440,512바이트입니다. Ollama도 모델을 띄울 때 `num_ctx`만큼 KV 공간을 미리 잡습니다.
6. **(b)** 이 변경은 속도를 올리려는 게 아니라 모양을 고정하려는 것입니다. prefill에서 638개 위치가 638칸만 보면 되는데 1,024칸을 다 보니 첫 토큰은 손해를 봅니다.
