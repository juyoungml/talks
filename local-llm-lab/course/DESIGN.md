# 평가 설계 · PyTorch로 Ollama 만들기

코스 "Ollama 안을 열어보자"(9강)에 붙일 퀴즈, 실습, 최종 프로젝트, 수료증 설계입니다.
학습자용 문서(`quizzes/`, `exercises/`)는 합니다체로 썼고, 이 문서는 작성자용입니다.

## 0. 원칙

- **문항은 그 자리에서 풀 수 있어야 합니다.** "4강에서 본 캐시"처럼 다른 강을 가리켜 기억을 더듬게 하지 않고, 필요한 코드(`steps/*.py`에서 그대로 복사)와 숫자를 문항 안에 직접 보여 줍니다. 저장소에 없는 코드(본문에 말로만 나오는 첫 시도 등)는 "본문 설명대로 다시 쓴 코드"라고 표시합니다.
- **숫자는 사이트와 실제 출력에서만 가져옵니다.** 퀴즈 문항의 숫자는 `site/chNN.html` 본문 또는 `examples/steps/NN_*.pass1.txt`에 있는 값입니다. 정답 해설에 계산이 들어가면 그 계산식을 적었습니다.
- **기계마다 속도가 다릅니다.** 실습과 체커는 절대 tok/s를 합격 기준으로 쓰지 않습니다. "같은 기계에서 이전 강 대비 몇 배" 또는 "같은 기계의 Ollama 대비"처럼 상대 기준만 씁니다.
- **실습은 `steps/NN_*.py`를 복사해서 고칩니다.** 원본은 다음 강의 출발점이라 건드리지 않게 합니다. 학습자 작업 폴더는 `work/`(git에서 무시)로 안내합니다.
- **정답은 결과로 확인합니다.** "코드가 정답과 같은가"가 아니라 "출력이 맞는가"(점수 차이, 1등 토큰 일치, 분포)를 봅니다. 구현 방식이 달라도 통과합니다.

## 1. 강별 학습 목표

| 강 | 제목 | 끝나면 할 수 있는 것 |
|---|---|---|
| 1 | 첫 토큰 꺼내기 | safetensors 가중치를 dict로 열고 구조(311개 텐서, 28층)를 읽는다. 채팅 템플릿 → 토큰 → embedding → 28층 → lm head → argmax 흐름을 설명하고 코드로 첫 토큰을 꺼낸다. GPU 시간을 `synchronize()` 후에 잰다. |
| 2 | 한 토큰씩 이어 쓰기 | greedy 생성 루프를 쓴다. 바이트 조각 토큰을 디코딩할 때의 처리를 이해한다. temperature, top-k, top-p 샘플링을 구현하고 결과 분포를 설명한다. 첫 토큰 시간과 decode tok/s를 구분해서 잰다. |
| 3 | 어디가 느린지 측정하기 | 스텝별 시간과 입력 길이별 forward 시간을 재서 병목 가설을 세운다. causal mask 때문에 앞 위치의 계산이 바뀌지 않음을 수치로 확인한다. 중복 계산량(31,752 대 685)을 계산한다. |
| 4 | KV cache | 층마다 k, v를 저장하는 캐시와 prefill/decode 두 단계를 구현한다. 캐시 결과가 전체 재계산과 같은지 검증한다. 토큰당 KV 메모리(112 KB)를 계산하고 GQA의 효과를 설명한다. |
| 5 | SDPA | 손으로 짠 attention을 `F.scaled_dot_product_attention`으로 바꾼다. 연산 수를 세고, prefill에서는 중간 결과 메모리, decode에서는 연산 수(GPU에 보내는 비용)가 병목임을 구분한다. |
| 6 | static cache | KV cache를 고정 크기 버퍼 + `index_copy_` + mask로 바꾼다. 위치를 텐서로 들고 다니는 이유(컴파일 조건)를 설명한다. 미리 잡는 메모리와 prefill 손해라는 대가를 안다. |
| 7 | torch.compile | decode 스텝을 `torch.compile(dynamic=False)`로 컴파일한다. 재컴파일 원인을 `TORCH_LOGS=recompiles`로 찾는다(stride 함정). 컴파일 시간과 스텝 시간을 따로 잰다. |
| 8 | INT8 가중치 | 행별 absmax INT8 양자화를 구현하고 오차를 잰다. 역양자화 후 곱하면 왜 느려지는지, INT8을 그대로 읽는 커널이 왜 필요한지 설명한다. 정밀도가 다른 비교의 공정성을 따진다. |
| 9 | 다시 비교하기 | 같은 조건으로 Ollama를 호출해 비교한다. 스텝당 읽는 바이트로 실효 대역폭과 이론 천장을 계산하고, 남은 개선 방향(prefill, 4비트, batching, speculative decoding)을 같은 원리로 설명한다. |

## 2. 형식과 이유

| 형식 | 어디에 | 왜 |
|---|---|---|
| **개념 퀴즈** (강마다 6~7문항, 객관식 + 단답) | `quizzes/NN.md` | 영상만 보고 넘어간 사람도 핵심 숫자와 인과("왜 빨라졌나")를 한 번 더 짚게 합니다. 단답은 계산 문항 위주라 채점이 명확합니다. |
| **코드 실습** (강마다 1~3개, 필수 1개 + 선택) | `exercises/NN.md` | 이 코스의 가치는 "직접 고쳐서 숫자가 바뀌는 걸 보는 것"입니다. 실습은 모두 `steps/` 파일을 고치거나 측정 코드를 붙이는 형태입니다. |
| **자동 체커** (필수 실습 중 결과가 결정적인 것) | `checks/check_NN_*.py` | 샘플링 분포, 캐시 결과 일치, 양자화 오차처럼 정답 범위를 숫자로 정할 수 있는 실습만 체커를 둡니다. 속도는 기계마다 달라서 체커 대상이 아닙니다. 견본: `checks/check_02_sampling.py`. |
| **최종 프로젝트** | `exercises/capstone.md` | 수료증을 "봤다"가 아니라 "할 수 있다"의 증거로 만들려면, 배운 기법을 처음 보는 조건에 적용하는 과제가 하나는 있어야 합니다. |

### 체커를 둘 수 있는 실습 (구현 우선순위 순)

| 실습 | 판정 방법 | 모델 필요 | 상태 |
|---|---|---|---|
| 2강 `sample()` 구현 | 합성 logits에서 top-k/top-p 집합, temperature 분포 일치 + (선택) 실제 첫 토큰 1,000번 분포 | 선택 (`--real`) | **견본 완성** |
| 4강 KV cache 구현 | 8스텝 동안 전체 재계산 대비 최대 차이 < 0.1, 1등 토큰 8/8 | 필요 | 설계만 |
| 6강 static cache | 4강 캐시와 같은 48토큰 출력, mask 모양 `[1, MAX_LEN]` 고정 | 필요 | 설계만 |
| 8강 INT8 양자화 | `int8` dtype, 행별 scale 모양, 1층 q_proj 평균 상대오차 ≈ 1%, 48토큰 출력이 FP16과 동일 | 필요 | 설계만 |
| 9강 대역폭 계산 | 학습자가 출력한 MB 값이 코드로 다시 센 바이트 수와 ±1% | 필요 | 설계만 |

체커는 학습자 파일을 `import`하지 않고 **함수 단위로 계약**을 정합니다. 2강은 "`sample(logits, temperature, top_k, top_p)` 하나가 들어 있는 파일"을 받습니다. `steps/*.py`는 맨 위에서 모델을 바로 돌리는 스크립트라 import하면 전체가 실행되기 때문입니다. 실제 모델이 필요한 체커는 `steps/02_generate.py`의 `# %% generate` 앞까지만 `exec`해서 가중치와 `forward`를 얻습니다(견본의 `--real` 참고). 이렇게 하면 `steps/`를 고치지 않고 재사용할 수 있습니다.

## 4. 합격 기준

두 단계로 나눕니다.

| 단계 | 조건 | 확인 방법 | 수료증 |
|---|---|---|---|
| **수강 완료** | 9개 퀴즈 각각 80% 이상 + 필수 실습 9개 | 자가 채점(정답표 공개). 체커가 있는 실습은 체커 통과 | 이름만 들어간 자가 발급 페이지. 검증 ID 없음 |
| **프로젝트 인증** | 수강 완료 + 최종 프로젝트 1개 통과 | 공개 저장소 + 실행 로그 + 보고서를 제출, 작성자가 검토 | 검증 ID가 있는 수료증(아래 5절) |

- 퀴즈는 몇 번이든 다시 풀 수 있습니다. 문항 수가 적어서(6~7개) 80%는 "한 문제까지 틀려도 됨"입니다.
- 최종 프로젝트는 합격/보완 두 가지로만 판정합니다. 보완이면 무엇이 빠졌는지 적어서 돌려줍니다.

### 부정행위에 대한 현실적인 태도

무료 자기주도 코스에서 퀴즈와 체커는 막을 수 없습니다. 정답표와 체커 소스가 공개되어 있고, 체커가 "통과 코드"를 출력해도 소스를 보면 위조할 수 있습니다. 그래서:

- **퀴즈와 실습은 학습 도구로만 씁니다.** 통과 여부를 서버에 모으지 않고, 수강 완료 단계에는 검증 ID를 주지 않습니다. 위조할 이유를 없애는 쪽입니다.
- **신뢰는 최종 프로젝트에만 겁니다.** 공개 저장소의 커밋 기록, 학습자 기계에서 나온 실행 로그(기기 이름, PyTorch 버전, 시각 포함), 자기 말로 쓴 보고서를 봅니다. 다른 사람 저장소를 그대로 복사하면 커밋 기록과 로그에서 드러나고, 수료증 검증 페이지가 그 저장소로 링크되므로 수료증을 보는 사람이 직접 확인할 수 있습니다.
- **LLM이 대신 짜는 것**은 막지 않습니다. 보고서에 "어디가 왜 빨라졌는지"를 학습자 기계의 숫자로 설명하게 하면, 코드를 누가 짰든 학습자가 이해했는지는 드러납니다. 검토 시 의심되면 짧은 추가 질문 하나(예: "KV 버퍼를 2,048칸으로 늘리면 9강의 대역폭 계산이 어떻게 바뀝니까?")를 보냅니다.
- **정답 예시 코드**(`checks/examples/`)는 체커 검증용입니다. 공개 저장소에 둘지는 미결정 사항입니다(8절).

## 5. 수료증 방식 비교

| | A. 자가 발급 페이지/PDF + 검증 ID | B. Open Badges 3.0 배지 (Certifier, POK 등) | C. Credly | D. YouTube Courses | E. 인프런 |
|---|---|---|---|---|---|
| 무엇이 남나 | 코스 사이트의 `verify/?id=…` 페이지, 인쇄용 PDF | 표준 형식의 디지털 배지(검증 가능한 자격 증명), LinkedIn에 추가 가능 | Credly 배지, LinkedIn 연동 | YouTube 안의 완료 배지 | 인프런 수료증 |
| 필요한 계정 | GitHub(이미 있음) | 발급 플랫폼 기관 계정 | Credly 기관 계약 | YouTube 채널, Courses 기능 자격 | 인프런 지식공유자 계정 |

| 인프라 | 정적 사이트(GitHub Pages) + 수료자 JSON 목록 | 없음(플랫폼이 호스팅) | 없음 | 없음 | 없음 |
| 검증 | 검증 페이지가 ID를 JSON에서 찾아 이름·날짜·프로젝트 링크 표시. 위조 PDF는 ID 조회로 걸러짐 | 표준 서명 검증. 가장 강함 | 플랫폼 검증 | YouTube 안에서만 의미 | 인프런 안에서만 의미 |
| 프로젝트 인증과 맞나 | 그대로 맞음. 발급 기준을 작성자가 정함 | 맞음. 발급은 수동 | 맞음 | 맞지 않음. 완료 기준이 시청/퀴즈 | 맞지 않음. 기준이 완강(시청률) |
| 단점 | 외부 인지도 없음. 수료자 이름을 공개 JSON에 올림(동의 필요) | 플랫폼 정책이 바뀔 수 있음. 영어 위주 UI | 개인 코스에 비해 과한 비용 | 기능이 채널마다 점진적으로 열림(Studio에서 자격 확인), 영상 퀴즈 연결은 되지만 코드 실습 확인 불가 | 무료 강의 수료증 발급 조건이 공식 문서로 확인되지 않음. 영상을 인프런에 다시 올려야 함 |

조사 메모(2026-11-20 웹 검색):
- YouTube Courses: 2022년 베타로 시작해 고급 기능 자격이 있는 채널로 넓히는 중이고, 영상에 연결된 퀴즈와 완료 배지를 지원한다는 보도가 있습니다. 공식 현재 상태는 YouTube Studio에서 직접 확인해야 합니다.
- 인프런: 무료 강의 수료증은 일부 강의에만 발급된다는 수강생 답변만 찾았고 공식 기준은 찾지 못했습니다. 인프런 고객센터 확인이 필요합니다.
- Credly/Open Badges 비용은 업체와 비교 사이트 자료이고 공식 가격표가 아닙니다.

### 추천: A로 시작하고, 원하면 나중에 B를 얹습니다

1. **A. 자가 발급 + 검증 ID**를 기본으로 합니다. 비용이 0이고, 이미 있는 정적 사이트에 페이지 두 개(수료증, 검증)와 JSON 파일 하나만 더하면 됩니다. "프로젝트를 검토하고 발급한다"는 이 코스의 기준을 그대로 담을 수 있습니다.
2. 수료자가 늘고 LinkedIn 표시 요청이 생기면 **B(Open Badges 3.0 무료 플랜)**를 추가합니다. 같은 수료자 목록에서 배지를 한 번 더 발급하는 것이라 A를 버릴 필요가 없습니다.
3. **YouTube Courses**는 수료증 수단보다 재생목록 정리 수단으로 봅니다. 채널에 기능이 열려 있으면 강마다 퀴즈 몇 문항(`quizzes/`의 객관식)을 연결하는 정도로 쓰면 됩니다.
4. **Credly, 인프런**은 지금 단계에서는 권하지 않습니다. Credly는 비용, 인프런은 영상 재업로드와 불명확한 무료 수료증 조건 때문입니다.

### A의 구체적인 흐름

```
학습자: GitHub Issue 양식 "최종 프로젝트 제출" 작성
        (이름 표기, 저장소 URL, 과제 번호, 실행 로그, 이름 공개 동의 체크,
         기기 이름, 2·4·5·6·7·8강 steps 실행 출력의 "이후 N tok/s" 줄)
작성자: 검토 → 합격이면 course/certificates/registry.json에 한 줄 추가 (PR)
        { "id": "OLM-26-7K3Q-9F", "name": "…", "date": "2026-12-01",
          "track": "B. 다른 모델에 적용", "repo": "https://github.com/…",
          "machine": "Apple M2 MacBook Air",
          "rates": { "2강": 2.9, "4강": 30.5, "5강": 35.2, "6강": 36.0, "7강": 52.8, "8강": 71.4 } }
배포:   GitHub Pages가 다시 빌드 → /course/certificate/?id=OLM-26-7K3Q-9F
        페이지가 registry.json을 읽어 수료증을 그림. 없는 ID면 "확인되지 않는 ID"
```

- ID 형식: `OLM-연도2자리-무작위4자리-검사2자리`. 무작위 부분은 헷갈리는 글자(0/O, 1/I)를 뺀 32자에서 뽑고, 검사 자리는 앞 부분의 해시입니다. 오타를 걸러 낼 뿐 보안 장치는 아닙니다. 보안은 "registry.json에 있느냐"로 정해집니다.
- 이름은 학습자가 원하는 표기를 그대로 쓰고, 이름 공개를 원하지 않으면 이니셜로 발급합니다.
- **수료증의 큰 숫자는 학습자가 직접 잰 값입니다.** 오른쪽 판의 "처음 → 마지막" decode 속도와 막대는 `rates`에서 그립니다. 기계마다 숫자가 달라서(코스 작성자의 M3 Pro는 3.6 → 92.2) 각자 자기 기계에서 만든 결과가 수료증에 남습니다. 검토할 때는 제출된 실행 출력 원문에서 값을 옮기고, 배수(마지막 ÷ 처음)가 코스 기준과 크게 다르면(예: 10배 미만, 50배 초과) 로그를 다시 확인합니다. 빠진 강이 있으면 그 막대는 그리지 않습니다.
- PDF는 수료증 페이지의 인쇄 스타일(A4 가로)로 브라우저에서 저장합니다. 따로 PDF 서버가 필요 없습니다.
- 견본: `certificate/sample.html` (정적 목업, ID 조회 로직은 아직 없음). `site/style.css`의 색 토큰을 옮겨 왔고, 사이트와 달리 Pretendard를 jsDelivr에서 불러옵니다. 수료증은 글꼴이 설치되지 않은 사람의 기기에서도 인쇄되기 때문입니다. 종이는 다크 모드에서도 밝게 둡니다.

## 6. 최종 프로젝트

`exercises/capstone.md`에 학습자용 안내가 있습니다. 세 트랙 중 하나를 고릅니다.

| 트랙 | 과제 | 합격 기준 (모두 같은 기계에서 잰 상대값) |
|---|---|---|
| A. 첫 토큰 줄이기 | 9강 "더 가려면" 첫 번째 항목. prefill이 1,024칸 대신 실제 길이만 보게 하고, 원하면 prefill도 컴파일 | 학습자 기계에서 08강 대비 첫 토큰 시간 감소를 측정해 보고. 출력 48토큰이 08강과 동일 |
| B. 다른 모델에 적용 | Qwen3-1.7B 등 같은 구조의 더 큰 모델에 04~08강 기법 적용 | 02강 방식(캐시 없음) 대비 decode 배수와, 9강 방식의 대역폭 계산을 보고. 공식 Transformers 구현과 첫 토큰 일치 |
| C. 대역폭 천장 다가가기 | KV 버퍼에서 채운 칸만 읽기, INT4 실험 등으로 9강의 80 GB/s를 올리기 | 9강 계산식으로 실효 GB/s를 구하고, 08강 대비 변화와 원인을 보고. 출력 품질 변화(48토큰 일치 여부)를 함께 보고 |

어떤 트랙이든 제출물은 같습니다: 공개 저장소, `REPORT.md`(무엇을 바꿨고 숫자가 어떻게 변했고 왜 그런지), 실행 로그 원문, 그리고 자기 기계에서 `steps/02, 04~08`을 실행한 출력(수료증 숫자로 쓰입니다).

## 7. `site/`, `videos/` 변경 제안 (이 세션에서는 고치지 않음)

1. **강 표기.** 사이트는 아직 "01장", "이번 장"입니다. YouTube 제목이 "N강"이니 사이트도 "N강"으로 맞추는 게 좋습니다. 퀴즈/실습 문서는 "N강"으로 썼습니다.
2. **각 강 끝에 링크 두 개.** 본문 마지막의 `uv run python steps/…` 블록 아래에 "이 강의 퀴즈", "이 강의 실습" 링크를 둡니다. `course/`가 사이트와 같은 서버(8896)에서 보이므로 상대 경로 `../course/quizzes/NN.md`면 됩니다. 마크다운을 그대로 보여 줄지 HTML로 바꿀지는 결정 필요(8절).
3. **본문 숫자와 예시 출력의 차이.** 같은 실행이 아니라 값이 다릅니다. 퀴즈는 본문 값을 썼지만, 학습자가 `examples/`를 같이 보면 헷갈릴 수 있습니다. 예: 1강 첫 토큰 223 ms(본문) / 252 ms(예시), 2강 4.0 tok/s / 3.4 tok/s, 3강 1토큰 19.5 ms / 20.0 ms, 4강 42.0 tok/s / 33.8 tok/s, 7강 컴파일 19.6초 / 2.9초(캐시된 두 번째 실행). 본문에 "실행마다 수치가 조금씩 다릅니다" 한 줄을 넣거나, 예시 출력을 본문과 같은 실행으로 맞추는 방법이 있습니다.
4. **3강 표의 라벨.** 텍스트 추출 시 "119.5 ms"처럼 길이와 시간이 붙어 보입니다(실제 화면은 표라서 문제없을 수 있음). 확인만 하면 됩니다.
5. **수료증 링크.** 9강 끝("처음으로 ↺" 옆)에 "최종 프로젝트와 수료증" 링크.
6. **영상 설명란.** YouTube 설명 끝에 "퀴즈와 실습: {사이트 주소}/course/" 한 줄.

## 8. 미결정 사항

1. **수료증 방식**: 추천은 A(자가 발급 + 검증 ID). B(Open Badges)를 처음부터 같이 할지.
2. **정답 공개 범위**: 퀴즈 정답표는 문서 아래에 바로 두었습니다. 실습 정답 코드(`checks/examples/`)를 공개 저장소에 둘지, 비공개로 둘지.
3. **수료자 명단 공개**: registry.json에 이름을 공개할지, 이니셜만 둘지, 비공개 저장소에서 ID → 해시만 공개할지.
4. **퀴즈 형식**: 지금은 마크다운입니다. 사이트 안에서 바로 채점되는 HTML 퀴즈(정적 JS, 서버 없음)로 바꿀지.
5. **체커 범위**: 견본은 2강 하나입니다. 4·6·8·9강 체커까지 만들지.
6. **최종 프로젝트 검토 인력**: 혼자 검토할 수 있는 양(월 몇 건)을 정하고, 넘으면 대기 목록으로 둘지.
7. **수료증에 들어갈 서명**: 작성자 이름/소속 표기 여부(견본은 "코스 작성자" 자리만 비워 둠).
