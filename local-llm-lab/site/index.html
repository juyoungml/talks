로컬 LLM 실험실

PyTorch로 만드는 추론 엔진

Ollama 안을 열어보자

회의록을 붙여 넣고 엔터를 쳤더니, 인터넷 연결도, API 키도 없이 노트북이 요약을 써 내려가기 시작합니다.

설치 한 줄, 명령 한 줄이면 끝입니다. 그런데 이 안에서 무슨 일이 일어나는지는 막상 잘 모르죠. 맨 아래 숫자도 그렇습니다. eval rate 78.64 tokens/s는 빠른 걸까요, 느린 걸까요? 무엇이 이 숫자를 정할까요?

이 글에서는 이걸 직접 만들어 보겠습니다. 재료는 Hugging Face에 공개된 1.5GB짜리 가중치 파일 하나와 PyTorch뿐입니다. 같은 모델, 같은 회의록으로 시작해서 Ollama처럼 답을 써 내려가게 만들고, 마지막에는 Ollama 옆에 나란히 놓고 속도를 재 볼 것입니다.

눈치챘겠지만 모델은 "세 가지"만 정리하라는 말을 무시하고 회의록을 통째로 다시 썼습니다. 0.6B는 아주 작은 모델이라 그렇습니다. 이 글에서 관심 있는 건 답이 얼마나 좋은지가 아니라, 답이 어떻게 나오는지입니다.

이 글의 순서

  1. 1부 · 일단 만들기
  2. 01 첫 토큰 꺼내기가중치 파일에서 첫 글자 하나를 꺼낸다
  3. 02 한 토큰씩 이어 쓰기답이 나온다. 그런데 너무 느리다
  4. 2부 · Ollama 따라잡기
  5. 03 어디가 느린지 측정하기
  6. 04 계산한 K, V 재사용하기 · KV cache
  7. 05 attention 커널 바꾸기 · SDPA
  8. 06 메모리 미리 잡아두기 · static cache
  9. 07 파이썬 오버헤드 줄이기 · compile
  10. 08 가중치를 INT8로 줄이기
  11. 09 다시 Ollama와 비교하기
따라 하려면

Apple Silicon Mac 기준입니다. MPS가 없으면 자동으로 CPU에서 돌아갑니다(느립니다). 처음 실행할 때 가중치 1.5GB를 받습니다.

git clone … && cd local-llm-lab
uv sync --python 3.12
uv run python steps/01_first_token.py

Ollama와 비교하고 싶다면 brew install ollama 후 ollama pull qwen3:0.6b-fp16.

01 · 1부 일단 만들기

첫 토큰 꺼내기

Ollama가 회의록을 받고 가장 먼저 내놓은 글자는 1이었습니다. 이번 장에서는 공개된 가중치 파일에서 이 첫 토큰을 직접 꺼냅니다.

파일은 steps/01_first_token.py 하나입니다. 글을 내려가면서 이 파일이 조금씩 자라는 걸 오른쪽에서각 절 아래에서 볼 수 있습니다.

모델 파일에는 뭐가 들어 있을까

"모델"이라고 하면 뭔가 거창한 프로그램 같지만, 내려받은 model.safetensors를 열어 보면 이름이 붙은 행렬 묶음입니다. 파이썬 딕셔너리로 그대로 읽힙니다.

텐서 311개, 파라미터 752M
  model.embed_tokens.weight                  [151936, 1024]
  model.layers.0.self_attn.q_proj.weight     [2048, 1024]
  model.layers.0.mlp.up_proj.weight          [3072, 1024]

이 311개가 전부입니다. 이름에 layers.0부터 layers.27까지 있는 걸 보면 같은 모양의 층이 28개 쌓여 있다는 것도 알 수 있습니다. 이제 남은 일은 이 행렬들을 어떤 순서로 곱하느냐입니다.

문장을 숫자로 바꾸기

행렬은 글자를 못 읽으니 먼저 문장을 정수로 바꿉니다. 토크나이저는 자주 나오는 글자 조각마다 번호를 붙여 둔 사전입니다.

Ollama 화면에서는 회의록만 붙여 넣었지만, 실제로 모델에 들어가는 건 채팅 템플릿으로 감싼 문장입니다. 누가 말하는지, 어디서부터 모델이 답할 차례인지를 특수 토큰으로 표시합니다.

템플릿 전 우리가 넘긴 messages
role"user"content

      

      

        템플릿 후 모델이 실제로 읽는 글 text
        

        
    
          
  • <|im_start|>user 여기부터 사용자 말
    • 
          
  • <|im_end|> 한 사람의 말이 끝남
    • 
          
  • <|im_start|>assistant 이제 모델이 말할 차례
    • 
          
  • <think> </think> 생각 단계를 비워 둠 (enable_thinking=False)
    • 
        

        
맨 끝이 "assistant 차례" 표시로 끝납니다. 그래서 모델이 다음에 쓸 글자는 곧 답의 첫 글자입니다.

      


      
이 글을 토크나이저에 넣으면 정수 배열이 나옵니다. 앞부분만 보면 이렇습니다.

      

        151644<|im_start|>
        872user
        198\n
        134379회의
        49664록
        20401의
        135763␣결정
        32129␣사
        … 630개 더
      

      
"회의록의 결정 사"까지가 토큰 8개입니다. 한글은 한 글자가 한 토큰일 때도, 두 글자가 한 토큰일 때도 있습니다. 회의록 전체는 638토큰이 됐습니다.


torch.Size([1, 638])

      

        토크나이저 후 638개 전부 보기
        
칸 하나가 토큰 하나입니다. 색은 경계를 보이려고 번갈아 칠했습니다.

        

        
점선 칸(렌1/2)은 눈여겨볼 만합니다. 사전에 통째로 없는 글자는 UTF-8 바이트 조각 2~3개로 쪼개집니다. "렌", "데", "첫" 같은 흔한 글자도 그래서 이 회의록에서만 106개, 전체의 17%가 이런 조각입니다. 한국어 글이 영어보다 토큰을 많이 먹는 이유 중 하나입니다.

      

    


    

      
숫자 하나를 벡터 하나로

      
토큰 번호는 그냥 이름표라서 계산에 쓸 수가 없습니다. 그래서 첫 번째 행렬 embed_tokens에서 그 번호의 행을 꺼냅니다. 151,936개 토큰마다 1,024개 숫자로 된 행이 하나씩 있습니다.


torch.Size([1, 638, 1024])

      
코드는 한 줄입니다. 이제 문장은 638개 위치 × 1,024차원 벡터입니다. 이 모양은 마지막 층을 지날 때까지 바뀌지 않으니 기억해 두면 좋습니다.


      
한눈에 보는 Qwen3 구조

      
층 안으로 들어가기 전에, 이 벡터가 어디를 지나 첫 토큰이 되는지 한 장으로 보면 이렇습니다. 상자를 누르면 그 부분을 설명하는 절로 갑니다.

      
    


    

      
토큰끼리 정보를 주고받는 attention

      
28개 층은 모두 같은 일을 합니다. 앞쪽 절반은 attention입니다. 위치마다 "앞에 나온 토큰 중 누구를 참고할까"를 점수로 매기고, 그 점수만큼 다른 위치의 정보를 섞어 옵니다.

      
코드가 조금 길지만 하는 일은 세 가지입니다.

      
    
        
  • q, k, v: 각 위치의 벡터를 행렬 세 개에 곱해 "찾는 것", "내 이름표", "내 내용"을 만듭니다.
    • 
        
  • rope: 위치마다 다른 각도로 q, k를 돌려서 순서 정보를 넣습니다.
    • 
        
  • mask: 답을 쓰는 모델은 미래를 볼 수 없으니, 각 위치는 자기와 그 앞만 보게 막습니다.
    • 
      

      
지금은 "이런 게 있구나" 정도면 충분합니다. 05장에서 이 함수를 다시 뜯어볼 것입니다.

    


    

      
토큰마다 따로 계산하는 MLP

      
뒤쪽 절반 MLP는 위치끼리 섞지 않고 각 위치의 벡터를 혼자 변환합니다. 1,024차원을 3,072차원으로 넓혔다가 다시 줄입니다.

      
중요한 건 block의 두 줄입니다. attention과 MLP의 결과를 원래 벡터에 더합니다. 그래서 층을 지나도 모양이 바뀌지 않습니다.


torch.Size([1, 638, 1024])

      
들어간 모양 그대로 나왔습니다. 그러니 같은 함수를 28번 반복해서 쌓을 수 있습니다.

    


    

      
다음 토큰 고르기

      
층을 다 지나고 나면 마지막 위치의 벡터만 꺼냅니다. 이 벡터를 151,936개 토큰 각각의 embedding과 내적하면 다음에 올 토큰의 점수가 나옵니다. Qwen3-0.6B는 입력에서 썼던 embed_tokens 행렬을 출력에서도 그대로 다시 씁니다.

      
아래 그림이 그 계산입니다. 띠 하나가 숫자 1,024개고, 주황은 양수, 파랑은 음수입니다. 행을 누르면 h와 그 행을 칸끼리 곱한 결과가 보입니다. 그 아래 선은 곱한 값을 왼쪽부터 하나씩 더해 간 것입니다. 선이 오른쪽 끝에서 멈춘 높이가 그 토큰의 점수입니다.


      

      
점수를 softmax로 확률로 바꾸면 이렇게 됩니다.

      
      
1이 60%로 1등입니다. Ollama도 답을 1.로 시작했죠. 2등 -도 그럴듯합니다. 목록을 1.로 시작할지 -로 시작할지 고민하고 있는 것입니다.

      
우리 코드가 정말 맞는지는 Hugging Face Transformers의 공식 구현과 같은 입력으로 비교해서 확인했습니다. 1등 토큰은 같고, 점수 차이는 FP16 반올림 수준(최대 0.05)입니다.

    


    

      
첫 토큰까지 걸린 시간

      
마지막으로 시간을 측정해 보겠습니다. GPU는 일을 받아 두고 나중에 처리하기 때문에, synchronize()로 끝날 때까지 기다린 다음에 시계를 봐야 합니다.


입력 638토큰 → 첫 토큰 '1': 223 ms

      
      
생각보다 나쁘지 않죠? Ollama보다 조금 느리지만, 파이썬 몇십 줄로 1초도 안 걸려서 첫 글자를 꺼냈습니다.

      
이제 답 전체를 쓰려면 이걸 반복하면 됩니다. 방금 나온 1을 입력 끝에 붙이고 다시 forward, 또 붙이고 다시 forward. 다음 장에서 해 볼 텐데, 거기서 이 숫자가 무너집니다.

uv run python steps/01_first_token.py
